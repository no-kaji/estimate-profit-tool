## 目的・背景

- 対象業務は、販売促進・イベント運営等のためのスタッフ派遣/プロモーション事業における
  「案件ごとの見積作成」と「収支管理(粗利計算)」。
- 現状Excel雛形(`references/雛型_見積収支計算書_Ver2.xlsx`)で個別に作成・集計している
  見積書・収支計算書を、一つのWebツールに統合し効率化する。
- 見積作成から収支計算・月次集計までを一連の業務フローとして扱う。

## 利用者

- 営業(見積作成が中心)
- 経理(収支計算・月次集計が中心)

## 参照Excel雛形から読み取った業務構造

雛形は以下のシートで構成されており、これがそのままツールの中核データモデルの土台となる。

### 1. 案件(収支計算書) — 案件1件につき1レコード
- **基本情報**: 部署、クライアント名、案件番号、案件名、契約期間(開始/終了)
- **スタッフ配置明細**(案件内に複数行):
  No、Trinity_ID(スタッフID)、スタッフ名、社保加入区分(済/未/外注)、職種
  (例: RO=ラウンダー、FS=フィールドスタッフ、MG=マネージャー等)、業務/店舗、備考、
  請求単価(日額/時間額)、通勤費・管理費・手当(請求月額)、稼働日数、
  支払単価(時給)、支払通勤費・手当・日数、基準労働時間(日/月)、
  普通残業・深夜残業・未請求有休時間(月)
- **自動計算**: 各スタッフ行から 売上高(人件費・通勤費・管理費・手当の合計)、
  原価(人件費基本・残業・深夜残業・未請求有給・通勤費・手当・事業主負担社保料)を算出し、
  スタッフごとの粗利益・粗利率を出す。事業主負担社保料は「年度別法定福利費率マスタ」
  (健保・介護・年金・児童拠出・雇保・労災・一般拠出、年度により料率が変わる)を用いて自動計算する。
- **案件収支サマリ**: 人件費・外注費・業務委託費(内、管理費/手当)・旅費交通費・通信費・
  消耗品・商品券・システム使用料・レンタル料・その他・調整、を費目別に集計し、
  売上高・売上原価・粗利・粗利率・販管費・営業利益・営業利益率を算出する。

### 2. 請求項目マスタ(「御見積請求項目」シート)
- 職種別の請求項目定義(プロモーションスタッフ/フィールドスタッフ/ラウンダー/
  マネージャー/事務局長/オペレーター/事務受付 等)と、各項目の説明文
- 経費項目定義(通勤交通費/営業交通費/手当/インセンティブ/旅費交通費/通信費/消耗品/
  商品券/システム使用料/レンタル料/運営費/研修費 等)
- キャンセルポリシーのパターンと、見積書に記載する定型文言
  (顧客都合のみ/天災等不可抗力も可/基本契約書締結済/覚書締結済、等)
- → 見積書作成時に、これらのマスタから項目・文言を選択して反映する想定。

### 3. 月次集計(「集計」シート、雛形時点の参考情報)
- 部署・クライアント・案件ごとに、**見積**と**実績**それぞれの売上高・粗利益・粗利率を並べ、
  増減、前月実績、前月差、請求日数、稼働日数を一覧表示する。
- ※このシート自体の画面(一覧・比較UI)はツールでは作らない。下記4のフラットレコードを
  出力し、可視化・比較はPower BI側で行う。

### 4. 経営ボード明細フォーマット(`経営ボード明細.xlsx`) — 出力先スキーマ
既存の経営ボード用Power BIレポートが読み込んでいる実データファイル。列構成は以下の
フラットな1行1レコード形式(会社×区分×年月×部門×取引先...の粒度):

| 列 | 内容 | 例 |
|---|---|---|
| 会社 | 会社名 | Backs |
| 区分 | 予算/実績 | 予算, 実績 |
| 常勤・CA | 就業形態区分 | 常勤, CA, その他 |
| 年月 | YYYYMM | 202604 |
| 統括名称 | 上位組織 | 10000営業本部 |
| 部門名称 | 部門 | 34000営業企画部 |
| 取引先名称 | クライアント名 | LG Electronics Japan |
| 地域区分 | 地域コード | 0 |
| セグメント | 事業セグメント | OS, 派遣, その他 |
| 商材 | 取扱商材 | デジタル, 金融 |
| 売上高 | 金額 | 470000 |
| 売上原価 | 金額 | 348240 |
| 粗利 | 金額 | 121760 |
| 常勤数 | 人数 | 0 |
| 販売管理費 | 金額 | 0 |
| ポジ数 | 人数 | 0 |
| 受注状況 | 区分 | 1.既存 |
| ユニット名称 | ユニット | 全国 |
| QT | 四半期 | 1QT〜4QT |

本ツールは、案件の見積レコード・実績レコードから **このスキーマと同一形式のレコードを
生成・蓄積**できればよい(区分列に「予算」=見積、「実績」=実績を出力)。
可視化・月次比較・ダッシュボードはPower BI側の役割であり、ツール側では作らない。

**Solution Architectへの申し送り**: 収支計算書側の項目(部署/クライアント/案件/
案件収支サマリの売上高・売上原価・粗利)と、経営ボード明細側の列
(統括名称/部門名称/取引先名称/地域区分/セグメント/商材/常勤・CA/常勤数/ポジ数/
受注状況/ユニット名称/QT)の間には未マッピングの項目がある。特に「年月」は
案件(契約期間)単位のデータを月次にどう分解するか(契約期間で月按分するか、
実績確定月のみ1行にするか等)を設計する必要がある。人間に追加確認するか、
Solution Architectの設計判断とするか、着手前に整理すること。

## 確定した運用ルール

- **見積と実績の関係**: 同一案件について「見積レコード」と「実績レコード」を別々に保持し、
  常に両方を比較できるようにする(上書き更新はしない)。
  - 案件作成時にまず見積レコードを作成し、稼働後に実績レコードを別途作成・入力する。
  - 月次集計では、案件ごとに見積と実績を並べて増減比較できること。

## スコープの前提(確定事項)

- **業務フロー**: 見積(案件+スタッフ配置の計画)作成 → (稼働後)実績入力 →
  収支自動計算 → 経営ボード明細形式でのレコード出力、を一連のフローとして通しで対応する。
  月次集計・可視化そのものはPower BIが担当し、ツールでは作らない。
- **出力形式**: 画面表示に加えて、PDF出力・Excel出力の両方が必要(Must)。
- **保存・管理**: 案件単位、部門単位など複数の切り口でストレージ内に保存・一覧管理できること。
  見積レコードと実績レコードは別レコードとして保持する。
- **計算ロジック**: 雛形の計算式(スタッフ行ごとの売上/原価/粗利、法定福利費率適用、
  案件収支サマリ集計)を踏襲する。年度別料率マスタ(健保・介護・年金・雇保・労災等)は
  年度が変わっても更新できるようマスタ管理する。
- **実行環境**: Webアプリ。依頼者の意向として Python + Streamlit での実装を想定
  (確定ではなく方向性。Solution Architectで技術選定として検証する)。
- **納期**: 特に期限なし。機能が揃った順にリリースしてよい(MoSCoWの優先度順で進行)。

## スコープ(MoSCoW)

### Must
- 案件(部署/クライアント/案件番号/案件名/契約期間)を登録できること
- 案件に対して見積レコード・実績レコードをそれぞれ作成・保存できること(同一案件で両方保持)
- 見積(概算/確定)作成時に、まず契約形式(業務委託/派遣/システム利用料/その他 等、
  今後増える前提)を1つ選択し、その見積内の明細行はすべて選んだ契約形式に紐づく
  計算パターンを使うこと(1見積=契約形式1つ)
- 明細行(人件費)は個人名ではなく「請求科目」(既存の請求項目マスタから選択、または
  その場で自由に新規作成)を単位として複数行入力でき、行ごとに単価×数量(計算パターン、
  例: 人日×日数、人月×月数、式×日数、式×月数、式のみ、時間×日数×月数)から
  売上・原価・粗利・粗利率が自動計算されること。社保加入区分は行ごとに保持できるが
  社内用の情報とし、見積書のプレビュー・出力には表示しないこと
- 経費行(外注費・旅費交通費等)は契約形式に縛られず、計算パターンを直接選択できること
- 契約形式マスタ・計算パターンマスタは初回リリースから画面で追加・編集できること
- 事業主負担の法定福利費(社保料率マスタ)を年度別に保持し、自動計算に反映できること
- 案件単位の収支サマリ(費目別内訳、売上高・売上原価・粗利・粗利率・営業利益)が
  自動集計されること
- 請求項目マスタ・キャンセルポリシー文言マスタを保持し、見積書作成時に選択・反映できること
- 見積書・収支計算書を画面表示に加え、PDF出力・Excel出力できること
- 見積レコード・実績レコードから、経営ボード明細.xlsxと同一スキーマのフラットレコードを
  生成・蓄積できること(区分列に予算=見積/実績を出力し、Power BI側で読み込めること)
- 案件を案件単位・部門単位で一覧・検索・再編集できること
- 概算見積の内容をコピーして確定見積レコードを新規作成できること
  (概算見積レコード自体は上書きされず保持される)
- 案件一覧の「新規案件登録」から、案件基本情報の入力→契約形式選択→見積明細入力
  (概算見積または確定見積)まで一連の流れで作成できること。既存案件に見積を追加する場合も
  同じ流れ(契約形式選択→明細入力)を使うこと
- 見積・実績レコードの編集時は、保存済みの明細行(人件費・経費)を読み込んで表示し、
  そこから修正できること
- 案件(基本情報+配下の見積・実績レコード・明細行すべて)を丸ごと複製して、
  新しい案件として保存できること(類似案件を作る際の入力の手間を減らす)

### Should
- 見積レコードの内容を実績レコード作成時にコピーして入力の手間を減らせること
- 請求項目マスタ・料率マスタを画面から編集・追加できること(Excel雛形の手修正を代替)

### Could
- 案件タイプ別の見積テンプレート化

### Won't(初期スコープ外)
- 月次集計・比較のダッシュボードや一覧画面(Power BIが担当するためツールでは作らない)
- 会計システムとの自動連携(仕訳連携等)
- 請求書発行・入金消込などの会計業務全般
- 外部システム(CRM等)との自動連携
- 複数ユーザーでの同時編集・承認ワークフロー(必要になれば別途要件化)

## Out of Scope

- 月次集計・可視化ダッシュボード(Power BIが担当)
- 会計ソフト・CRM等、外部システムとの自動連携
- 請求・入金管理などWon'tに記載の会計業務

## Acceptance Criteria

- 案件を登録し、見積レコードとしてスタッフ配置明細を入力した結果、雛形と同じ計算式で
  スタッフごとの売上・原価・粗利・粗利率、および案件収支サマリ(売上高・粗利・粗利率・
  営業利益)が算出されること。
- 同一案件に対し実績レコードを別途作成・入力した結果、見積レコードの値が変更されずに
  両方が保持されること。
- 見積レコード・実績レコードを出力した結果、経営ボード明細.xlsxと同一の列構成を持つ
  レコード(区分=予算/実績)が生成され、Power BIで読み込み可能な形になっていること。
- 法定福利費率マスタを年度で切り替えた結果、該当年度の案件計算に反映されること。
- 見積書を出力した結果、請求項目マスタ・キャンセルポリシー文言マスタの内容が反映された
  状態で、画面表示・PDF・Excelのいずれでも確認できること。
- 保存済みの案件を、案件単位・部門単位で一覧から検索・再編集できること。
