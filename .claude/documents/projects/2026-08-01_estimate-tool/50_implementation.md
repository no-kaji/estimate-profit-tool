## 実装した内容

### データモデル(`app/models.py`)
`30_architecture.md`のER図に沿って実装。Project / FinancialRecord / LineItem /
CostLine / ContractType / PricingPattern / ContractTypePattern /
InsuranceRateMaster / BillingItemMaster / CancellationPolicyMaster。

### 計算ロジック(`app/services/calc.py`)
- `pattern_amount`: 単価×数量1×数量2×数量3の汎用式
- `calc_line_item`: 明細行(人件費)の売上・原価・粗利
- `calc_cost_line_amount`: 経費行の金額
- `calc_financial_record_summary`: レコード単位の集計
- DBに依存しない純粋関数として実装し、`tests/test_calc.py`で単体テストを用意
  (ただしローカルで`pytest`を実行できていないため、テストがグリーンであることは未確認)。

### 初期マスタデータ(`app/seed.py`)
契約形式(業務委託/派遣/システム利用料/その他)・計算パターン・
令和7年度(西暦2025年度)法定福利費率・請求項目・キャンセルポリシーの初期データを、
参照Excel雛形の値をもとに投入。アプリ初回起動時に自動シードする。

### 画面(Streamlit)
- `Home.py`: エントリーポイント。DB初期化・マスタシードを実行。
- `pages/01_案件一覧.py`: 検索・新規案件登録(登録後そのまま見積入力へ)・複製。
- `pages/02_見積入力.py`: 契約形式選択(Step1)→明細入力(Step2)。概算見積/確定見積/実績を
  同一画面で扱う(Design Brief通り、03_実績入力は独立ページを作らずrecord_type選択で兼用)。
  概算見積→確定見積のコピー作成ボタンを実装。
- `pages/05_マスタ管理.py`: 契約形式・計算パターン・請求項目・キャンセルポリシー・
  法定福利費率マスタの編集(Must/Should双方を含む)。

## アーキテクチャとの既知の差異

- ディレクトリ構成: `30_architecture.md`は`app/main.py`+`app/pages/`を想定していたが、
  Streamlitのマルチページ機構(エントリースクリプトと同階層に`pages/`が必要)に合わせ、
  エントリーポイントをリポジトリ直下`Home.py`、`pages/`もリポジトリ直下に配置した。
  `app/`はDB・モデル・計算ロジックのみを置く純粋なPythonパッケージとした。

## 2026-08-06 データ永続化: PostgreSQL(VPS)+SSHトンネルへ切替

- **既知の制約(Streamlit Cloudの一時ストレージ)を解消**: 依頼者が用意したXserver VPS
  (AlmaLinux 10、IP: 162.43.51.134)上に、他アプリ(backs-system-portal等)と同居する形で
  専用データベース`estimate_tool`・専用ロール`estimate_app`をPostgreSQLに新規作成した。
- PostgreSQL自体は`127.0.0.1:5432`のみで待ち受け、外部には公開していない
  (VPSの既存セキュリティ方針に合わせ、ポート開放やpg_hba.conf変更は行わない)。
  代わりに、専用デプロイユーザー`estimate-tool-deploy`(sudo権限なし、鍵認証のみ)を
  経由するSSHトンネル方式で接続する。
- `app/db.py`: Streamlit Secretsに`[postgres]`/`[ssh_tunnel]`設定があればSSHトンネル経由で
  PostgreSQLに接続し、無ければ従来通りSQLite(非永続、ローカル開発用)にフォールバックする
  ように変更。`sshtunnel`・`paramiko`・`psycopg2-binary`を依存関係に追加。
- これにより、Streamlit Cloudのアプリ再起動(Reboot app)を行ってもデータが消えなくなった
  (PostgreSQL側にデータが永続化されるため)。
